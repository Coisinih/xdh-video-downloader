# VidNest 项目总结

## 1. 项目定位

VidNest 是一个前后端分离的自托管公开视频下载工具。用户粘贴公开视频链接，系统解析标题、封面、时长与可用格式后，由浏览器触发下载。

项目封装 `yt-dlp` 源码，不修改其上游实现；`ffmpeg` 用于服务端下载时的媒体合并。

## 2. 已交付功能

- Vue 3 + Vite 简体中文下载页，适配桌面与移动端。
- FastAPI 解析接口：返回视频元数据、封面与格式列表。
- 同源封面代理，避免 HTTP 封面、跨域或 Referer 导致浏览器不显示封面。
- 浏览器下载：直连可 302 到媒体源；需要 Referer、User-Agent 或 Origin 时自动使用流式代理，并支持 Range 请求。
- 服务端下载任务：进度、临时文件与两小时有效的交付地址。
- 内存化任务、解析与交付令牌；服务重启后清空。
- SSRF 防护、格式 ID 白名单、受控子进程调用、超时/并发/大小限制及临时记录清理。
- Docker Compose 部署：Nginx 前端反代与 FastAPI 后端。

## 4. 当前限制

- 仅面向有权保存的、公开且不需要登录、Cookie、DRM 或付费授权的内容。
- 平台与具体作品是否可用取决于上游访问策略和 `yt-dlp` 当前版本。
- 当前服务器出口在测试时被抖音与 YouTube 的会话/反机器人验证拦截，因此这两个平台不作为已验证支持范围。
- 西瓜视频、小红书等部分平台在测试时需要会话或未返回可用视频格式。
- 不实现 Cookie 上传、登录态伪造、验证码绕过或 DRM 绕过。

## 5. 维护指引

1. 升级 `backend/vendor/yt-dlp` 源码前，先在测试环境验证 B站、AcFun、虎牙样本。
2. 保持 `yt-dlp` 作为独立 vendored 源码目录；不要直接修改其提取器代码。业务适配放在 `backend/app/ytdlp.py`。
3. 每次改动下载交付逻辑后，验证封面代理、带请求头的流式代理、Range 请求和中文文件名。
4. 生产环境应配置文件大小、并发量、磁盘空间与允许来源域名；对外提供服务前应补充 IP 限流与可观测性。

## 6. 验证记录

- 后端单元测试：`pytest tests -q -p no:cacheprovider`，最近通过 4 项。
- 前端构建/测试曾在受限 Windows 沙箱因 `esbuild` 进程创建被拒绝（`EPERM`）而无法运行；这不是测试断言失败。建议在本地正常权限或 Docker 构建环境重新执行 `npm test` 与 `npm run build`。
